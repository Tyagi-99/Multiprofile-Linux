# Multiprofile Linux — Fingerprint & Identity Model

Version: 1.8.0  
Status: Deterministic & Coherent Configuration Model  

---

## 1. Design Principles: Consistency Over Hyper-Spoofing

Fingerprinting engines often fail by attempting aggressive, scattered JavaScript overrides that introduce internal contradictions (e.g., claiming a Windows user agent while leaving Linux WebGL renderer strings, exposing zero plugins, or sending desktop Client Hints with mobile touch events).

Multiprofile Linux adheres to three core rules:
1. **Internal Coherence**: Every profile component (User Agent, Client Hints, Platform, Screen Geometry, CPU Cores, Memory, WebGL Vendor/Renderer, Touch Capability) is derived from a unified platform pool.
2. **Dual-Tier Alignment (Wire + DOM)**: Browser identity is established both at the HTTP network level (via Chrome DevTools Protocol `Network.setUserAgentOverride`) and at the JavaScript execution level (via early extension injection).
3. **Environment Reality Respect**: The browser never contradicts its physical Linux environment by claiming dedicated hardware GPU acceleration when running in a headless container without `/dev/dri` access.

## 2. Deterministic Seed Architecture

Each profile has a stable 32-bit positive integer seed (`seed`), stored in `profiles.json`:
- **Persistence Across Restarts**: The seed is retained in the profile configuration. Re-launching Profile A today, tomorrow, or after a host reboot produces identical hardware parameters, screen geometries, and stable device IDs.
- **Profile Independence**: Profile A and Profile B have distinct seeds, producing different hardware configurations.
- **Fresh Identity on Clone**: When `clone_profile()` is invoked, a fresh random seed is generated by default across all clone modes (`config_only`, `config_and_cookies`, `full_session`), ensuring cloned instances do not share hardware fingerprints.


## 3. Dual-Tier Identity Synchronization

### 3.1 Network / Wire Tier (`cdp_identity.py`)
Standard extension scripts execute only inside the page context. They cannot modify initial HTTP request headers such as `User-Agent`, `Sec-CH-UA`, `Sec-CH-UA-Platform`, `Sec-CH-UA-Mobile`, or `Sec-CH-UA-Arch`.

To solve this gap, Multiprofile Linux connects to the profile's local CDP socket (`127.0.0.1:<port>`) immediately after launch and executes:
```json
{
  "method": "Network.setUserAgentOverride",
  "params": {
    "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
    "acceptLanguage": "en-US,en",
    "platform": "Win32",
    "userAgentMetadata": {
      "brands": [
        {"brand": "Google Chrome", "version": "131"},
        {"brand": "Chromium", "version": "131"},
        {"brand": "Not-A.Brand", "version": "99"}
      ],
      "fullVersionList": [
        {"brand": "Google Chrome", "version": "131.0.6778.86"},
        {"brand": "Chromium", "version": "131.0.6778.86"},
        {"brand": "Not-A.Brand", "version": "99.0.0.0"}
      ],
      "platform": "Windows",
      "platformVersion": "15.0.0",
      "architecture": "x86",
      "bitness": "64",
      "model": "",
      "mobile": false
    }
  }
}
```
This guarantees that initial HTTP GET headers exactly match the JavaScript execution environment.

### 3.2 JavaScript / DOM Tier (`evasion.js`)
Injected at `run_at: document_start` in the MAIN world. Configured via `__MP_INLINE_CFG__`:
- **Hardware & CPU/Memory**: `navigator.hardwareConcurrency`, `navigator.deviceMemory`.
- **Screen Geometry**: `screen.width`, `screen.availHeight`, `window.devicePixelRatio`.
- **Touch Capabilities**: `navigator.maxTouchPoints` (0 for desktop, >0 for mobile).
- **Plugins & MimeTypes**: Populates desktop profiles with 3 standard Chromium PDF viewer plugins (`PDF Viewer`, `Chrome PDF Viewer`, `Chromium PDF Viewer`). An empty `navigator.plugins` list is an immediate automation indicator.
- **Window.Chrome Supplementation**: Ensures `window.chrome.app`, `window.chrome.csi`, `window.chrome.loadTimes`, and `window.chrome.runtime` exist and present native function signatures (`toString()` yields `function () { [native code] }`).
- **Connection Information**: Populates `navigator.connection` with realistic downlink, effectiveType, and RTT properties.
- **Stable Media Device IDs**: Traps `navigator.mediaDevices.enumerateDevices` to return consistent, seeded 64-character hexadecimal IDs for audio/video inputs across page navigations.
- **Silent Operation**: Extension operates strictly silently. No `console.log` statements are emitted in the browser console.

## 4. GPU & WebGL Handling

The launcher detects system graphics capabilities via `/dev/dri/renderD*` and `/proc/driver/nvidia`:
- **Hardware Available**: Launches with `--use-gl=angle` and `--enable-gpu-rasterization`.
- **Headless / Container**: Launches with `--use-gl=swiftshader` and `--disable-gpu`.
- **Invariant**: The system never runs with `--disable-gpu` while simultaneously spoofing a discrete hardware GPU string in WebGL.

## 6. 1.6.0 Additions: Inspector Components, Device Coherence, CDP Brand Fix

### 6.1 Fingerprint inspector (`GET /api/profiles/<id>/fingerprint`)
The report now carries per-component `expected` blocks (Navigator, Client
Hints, Screen, Touch, …) so callers can inspect exactly what the profile
claims in each domain. See `docs/PROFILE_CONSISTENCY.md` for the coherence
engine that cross-checks them.

### 6.2 Device-preset coherence
When a profile is created with `deviceId`, the Screen component pins exactly
to the preset viewport × DPR (measured: Pixel 9 → `411x923@2.626`, matching
the declared preset geometry within the ±1 px validator tolerance), and the
Navigator/Client-Hints components carry the preset's Android UA and brand
metadata. Honest caveat: the legacy top-level `fingerprint` block may still
reflect the stored legacy desktop fingerprint; the inspector `components`
are the preset-coherent view.

### 6.3 CDP brand metadata shape (fixed in 1.6.0)
`MobileProfileConfig.user_agent_metadata()` previously emitted
`fullVersionList` entries with `fullVersion` keys, which real CDP rejects
(`Network.setUserAgentOverride` returned "Invalid parameters: missing
fullVersionList.version"). Both brand lists now emit CDP's exact
`{brand, version}` shape. Measured after the fix via live DevTools against
Chromium 152: `Emulation.setDeviceMetricsOverride` OK,
`Emulation.setTouchEmulationEnabled` OK, `Network.setUserAgentOverride` OK,
with the page reporting the applied geometry, `maxTouchPoints > 0`, and the
Android UA.

## 7. Known Limitations & Technical Boundaries (unchanged from 1.5.0)

1. **Linux Font Subsystem**: Linux renders fonts using FreeType/Fontconfig, which produces slightly different antialiasing sub-pixel geometry compared to DirectWrite (Windows) or CoreText (macOS). This cannot be eliminated without compiling a custom Chromium engine.
2. **Audio Hardware Latency**: AudioContext buffer timing and sample rate clocks reflect the host ALSA/PulseAudio/PipeWire subsystem.
3. **OS-Level Network Sockets**: TCP window size, initial congestion window, and SYN packet options remain characteristic of the Linux host kernel.
